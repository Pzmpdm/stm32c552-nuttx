# STM32C552VET6 NSH 完整适配计划

> 实施时使用 superpowers:executing-plans 按任务推进，逐项记录验证结果。

**目标**　让实体板的 USART1 NSH 成为可稳定使用的开发控制台，并用 Renode 对同一固件持续回归。

**架构**　保持现有 `stm32c552vet6-devkit:nsh` 配置作为入口，复用 STM32 串口、通用板级初始化和 NuttX Apps。保留首阶段冒烟测试，增加独立功能回归。实体板验收使用通过 Renode 测试的同一构建产物。

**工具**　NuttX、NuttX Apps、Arm GNU Toolchain、CMake/Ninja、GNU Make、Renode 1.17.0、Robot Framework、SWD 探针、3.3 V USB 转串口。

**基线**　[首阶段说明](../../../README.md)和[现有 Renode 测试](../../../renode/nsh.robot)。

## 范围

- 控制台保持 USART1、115200 8N1，PA9/TX 为 H4.4，PA10/RX 为 H4.6。
- 保持 Flash 起址 `0x08000000`、48 MHz HSIDIV3 和 64 KiB SRAM1。
- 完整开发控制台包括交互、系统诊断、临时文件与脚本、已注册应用和稳定性。持久化存储、USB CDC、远程 Shell、高级行编辑和 SRAM2 单列后续阶段。
- 以 CMake/Ninja 产物为实体板验收镜像。GNU Make 作为构建兼容性回归。

## 1. 补齐现有配置的 Renode 功能回归

文件为 `renode/nsh-regression.robot`，继续复用 `renode/boot.resc`，保留 `renode/nsh.robot` 的原有验收。

- [ ] 新增 `Serial Input Recovers After Invalid Lines`。验证退格修正、空行、CR 和 CRLF、连续两条命令及未知命令后的恢复。当前 `CONFIG_LINE_MAX=64`，用无副作用的输入覆盖 63、64 和 65 字节边界，记录截断或分行表现，每次用独立标记验证下一条短命令仍可执行。
- [ ] 新增 `NSH Exposes System Diagnostics`。检查 `help` 列出已注册的 `dd`，`ps` 有任务行，`free` 有可用堆数据，`ls /dev` 可见 console，`ls /proc` 可见任务目录。
- [ ] 新增 `NSH Waits For A Registered Application`。执行 `dd if=/dev/zero of=/dev/null bs=16 count=4`，确认复制 64 字节的统计先于下一次提示符，并验证错误参数后的下一条命令正常。
- [ ] 运行原有冒烟和新回归。所有断言通过才进入下一阶段。串口断言区分输入回显和实际命令输出。

## 2. 加入临时文件和脚本验收

修改 `nuttx/boards/arm/stm32c5/stm32c552vet6-devkit/configs/nsh/defconfig` 和 `renode/nsh-regression.robot`。把可写文件放在 `/tmp`，沿用板级通用初始化挂载 tmpfs。

- [ ] 新增 `NSH Runs A Script From Tmpfs`。通过串口在 `/tmp/nsh-test` 中用 `>` 和 `>>` 创建两行文件，复制后用 `cat` 校验内容，运行含变量、`if` 和唯一输出标记的小脚本。覆盖缺失文件报错，删除测试文件后检查目录可清理。
- [ ] 在现有配置上先确认 `/tmp` 文件测试失败，然后启用 `CONFIG_FS_TMPFS=y`。通过新 CMake 构建目录重新展开 defconfig，检查最终配置中 `CONFIG_LIBC_TMPDIR="/tmp"`，用通用板级初始化完成挂载。
- [ ] 新增 `NSH Recovers Resources After Repeated Commands`。预热后执行 100 轮固定的临时文件写读删除，确认每轮得到预期输出。在第 0、50、100 轮后采样 `free` 和 `ps`，活动任务数回到基线，两个后续堆样本均较基线少于 1 KiB，且无持续增长的堆占用。
- [ ] 从干净配置构建 CMake/Ninja 和 GNU Make，两个 ELF 都跑原有冒烟和新回归，保留结果及内存占用。确认向量表和 Flash 仍从 `0x08000000` 起，静态数据和堆位于 SRAM1。

## 3. 实体板验收并归档证据

需要实体板、SWD 探针和 3.3 V USB 转串口。保存固件 SHA-256、烧录和串口日志到 `build/nsh-hardware/`，最终结果写入 `README.md`。

- [ ] 烧录已通过 Renode 回归的 CMake/Ninja BIN，按 `0x08000000` 编程并读回校验。串口交叉连接 TX/RX 并共地，记录烧录文件散列与编译配置。
- [ ] 执行 10 次断电重启和 10 次 NRST 复位。每次观察到 `nsh>` 后执行一条带本轮编号的命令，要求 20 次全通过。
- [ ] 实测逐字输入、连续粘贴接近行长上限的合法命令、退格和行结束。使用串口脚本核对至少 100 条带序号的命令结果，零漏行、乱码或失去提示符。测试 `sleep 1` 后能继续交互，并复测诊断命令、临时文件、脚本和注册应用。
- [ ] 持续运行 30 分钟，定期执行命令，结束前重跑功能检查并比较 `free` 与 `ps`。要求无意外复位、卡死或残留任务。若实体板测试未完成，单独记录已通过的仿真项目。

## 验收记录

从工程根目录运行现有 README 的 CMake 构建流程。测试时从 `build/renode` 执行：

```sh
"$RENODE_HOME/renode-test" ../../renode/nsh.robot ../../renode/nsh-regression.robot
```

第二个构建路径用 `--variable ELF:/absolute/path/to/nuttx` 跑同一套测试。
两个构建的报告均需零失败。实体板记录必须能对应到同一份已通过仿真的固件；
Renode 的固定时钟与 UART FIFO 模型限制由实体板结果补足。
